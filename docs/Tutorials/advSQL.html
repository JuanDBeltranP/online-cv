Advanced SQL: Market Analytics in the Database

Written in 2024. All examples use public data and are for learning only, not investment advice.

In SQL 101 we built a small database of softs prices and exports. Here we push more of the analysis into SQL itself: rolling statistics, returns, spreads, seasonal comparisons and ranking. Doing this in the database keeps calculations consistent across every notebook and dashboard that reads from it.

All examples use SQLite 3.25+ (window functions). The same syntax works in PostgreSQL and BigQuery with minor changes.

1. Window functions: moving averages

A 20-day and 100-day moving average for cocoa:

SELECT date,
       settle,
       AVG(settle) OVER (ORDER BY date ROWS BETWEEN 19 PRECEDING AND CURRENT ROW)  AS ma20,
       AVG(settle) OVER (ORDER BY date ROWS BETWEEN 99 PRECEDING AND CURRENT ROW)  AS ma100
FROM prices
WHERE symbol = 'CC'
ORDER BY date;

PARTITION BY runs the same calculation separately for each market:

SELECT symbol, date, settle,
       AVG(settle) OVER (PARTITION BY symbol ORDER BY date
                         ROWS BETWEEN 19 PRECEDING AND CURRENT ROW) AS ma20
FROM prices;

2. Returns and volatility with LAG

WITH r AS (
  SELECT symbol, date, settle,
         LN(settle / LAG(settle) OVER (PARTITION BY symbol ORDER BY date)) AS log_ret
  FROM prices
)
SELECT symbol, strftime('%Y', date) AS year,
       ROUND(SQRT(252) * SQRT(AVG(log_ret * log_ret) - AVG(log_ret) * AVG(log_ret)), 3) AS ann_vol
FROM r
WHERE log_ret IS NOT NULL
GROUP BY symbol, year
ORDER BY symbol, year;

(SQLite needs its math extension for LN and SQRT; recent Python builds include it.) Run this and the 2024 cocoa row stands out: the 2023/24 rally came with volatility far above anything in the previous decade.

3. Common table expressions for readable logic

CTEs (WITH ...) break long queries into named steps. Here we flag days when cocoa moved more than three rolling standard deviations, a simple anomaly alert:

WITH r AS (
  SELECT date, settle,
         settle / LAG(settle) OVER (ORDER BY date) - 1 AS ret
  FROM prices WHERE symbol = 'CC'
),
s AS (
  SELECT date, settle, ret,
         AVG(ret) OVER w AS mu,
         SQRT(AVG(ret * ret) OVER w - AVG(ret) OVER w * AVG(ret) OVER w) AS sd
  FROM r
  WINDOW w AS (ORDER BY date ROWS BETWEEN 60 PRECEDING AND 1 PRECEDING)
)
SELECT date, settle, ROUND(ret * 100, 2) AS pct_move
FROM s
WHERE ABS(ret - mu) > 3 * sd
ORDER BY date DESC;

Note the window ends at 1 PRECEDING, so today’s move is compared with history only. Letting today leak into its own baseline is a classic mistake.

4. Calendar spreads

If you store individual contract months (a contract column such as CCN24, CCU24), you can compute spreads with a self-join:

SELECT a.date,
       a.settle AS jul,
       b.settle AS sep,
       a.settle - b.settle AS jul_sep_spread
FROM futures a
JOIN futures b ON a.date = b.date
WHERE a.contract = 'CCN24'
  AND b.contract = 'CCU24'
ORDER BY a.date;

A wide positive spread (backwardation) usually signals tight nearby supply, which is exactly what the cocoa curve showed through 2024.

5. Seasonal comparisons

Exports this season versus last season, month by month:

WITH s AS (
  SELECT origin, month, tonnes,
         CASE WHEN CAST(strftime('%m', month) AS INT) >= 10
              THEN CAST(strftime('%Y', month) AS INT)
              ELSE CAST(strftime('%Y', month) AS INT) - 1 END AS season_start
  FROM exports
  WHERE commodity = 'Cocoa'
)
SELECT cur.origin, cur.month, cur.tonnes,
       prev.tonnes AS last_season,
       ROUND(100.0 * (cur.tonnes - prev.tonnes) / prev.tonnes, 1) AS pct_change
FROM s cur
LEFT JOIN s prev
  ON prev.origin = cur.origin
 AND prev.month  = date(cur.month, '-1 year')
WHERE cur.season_start = 2023
ORDER BY cur.origin, cur.month;

Cumulative season-to-date totals with a running sum (reusing the same s CTE):

-- WITH s AS (...) as above
SELECT origin, month,
       SUM(tonnes) OVER (PARTITION BY origin, season_start ORDER BY month) AS season_to_date
FROM s;

6. Ranking

Top three origins per commodity by exports in a season:

SELECT * FROM (
  SELECT commodity, origin, SUM(tonnes) AS total,
         RANK() OVER (PARTITION BY commodity ORDER BY SUM(tonnes) DESC) AS rnk
  FROM exports
  WHERE month BETWEEN '2022-10-01' AND '2023-09-01'
  GROUP BY commodity, origin
)
WHERE rnk <= 3;

7. Views and indexes

Save logic you reuse as a view, and index the columns you filter on:

CREATE VIEW v_cocoa_daily AS
SELECT date, settle,
       AVG(settle) OVER (ORDER BY date ROWS BETWEEN 19 PRECEDING AND CURRENT ROW) AS ma20
FROM prices WHERE symbol = 'CC';

CREATE INDEX idx_prices_symbol_date ON prices(symbol, date);
CREATE INDEX idx_exports_origin_month ON exports(origin, month);

8. Transactions

Load each day’s data inside a transaction, so a failed load never leaves half a day in the table:

BEGIN;
INSERT INTO prices (symbol, date, settle, volume) VALUES ('KC', '2024-06-28', 226.25, 31000);
-- ... the rest of the day's rows
COMMIT;   -- or ROLLBACK; if anything failed
