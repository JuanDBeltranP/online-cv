Hyperparameters in Regression, Part 1: Tuning Without Look-Ahead

Written in 2024. All examples use public data and are for learning only, not investment advice.

In Regression 101 we explained weekly sugar returns with crude oil, the Brazilian real and the dollar. Here we tune the regularisation strength of Lasso, Ridge and Elastic Net. The key lesson is that standard k-fold cross-validation is wrong for market data.

1. What is a hyperparameter?

A hyperparameter is set before training rather than learned from the data. In Lasso and Ridge, alpha controls how hard coefficients are pushed towards zero. Too small and the model overfits noise; too large and it ignores real drivers.

2. Why ordinary cross-validation leaks

KFold(shuffle=True) mixes weeks from 2023 into the training set and then tests on 2016. The model has effectively seen the future. In markets this makes every model look better than it will ever be in live use.

The fix is TimeSeriesSplit, which always trains on the past and validates on the period that follows:

from sklearn.model_selection import TimeSeriesSplit
tscv = TimeSeriesSplit(n_splits=5, gap=1)   # gap avoids overlap at the boundary

for i, (tr, va) in enumerate(tscv.split(X_train)):
    print(i, X_train.index[tr[0]].date(), "to", X_train.index[tr[-1]].date(),
          "| validate", X_train.index[va[0]].date(), "to", X_train.index[va[-1]].date())

3. Grid search with a pipeline

Put the scaler inside a pipeline so it is refitted on each training fold. Scaling on the full sample is another quiet source of leakage.

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Lasso
from sklearn.model_selection import GridSearchCV
import numpy as np

pipe = Pipeline([("scale", StandardScaler()), ("model", Lasso(max_iter=10000))])

grid = GridSearchCV(
    pipe,
    param_grid={"model__alpha": np.logspace(-5, -1, 20)},
    cv=tscv,
    scoring="neg_mean_absolute_error",
)
grid.fit(X_train, y_train)

print("Best alpha:", grid.best_params_)
print("CV MAE:", -grid.best_score_)

4. Randomised search

When there are several hyperparameters, sampling is faster than an exhaustive grid. Elastic Net has two:

from sklearn.linear_model import ElasticNet
from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import loguniform, uniform

pipe = Pipeline([("scale", StandardScaler()), ("model", ElasticNet(max_iter=10000))])

rand = RandomizedSearchCV(
    pipe,
    param_distributions={"model__alpha": loguniform(1e-5, 1e-1),
                         "model__l1_ratio": uniform(0, 1)},
    n_iter=50, cv=tscv, scoring="neg_mean_absolute_error", random_state=42,
)
rand.fit(X_train, y_train)
print(rand.best_params_)

5. Final check on untouched data

Only after tuning do we look at the test period, once:

from sklearn.metrics import mean_absolute_error
best = rand.best_estimator_
print("Test MAE:", mean_absolute_error(y_test, best.predict(X_test)))

If test performance is much worse than cross-validated performance, the relationship has probably shifted, or the model was overfit. Both are common in softs, where regimes change with weather, policy and positioning.

6. Practical tips

  • Choose the metric that matches the use: MAE for typical error, directional accuracy if you care about the sign.
  • Prefer simple models when cross-validated scores are close; they hold up better out of sample.
  • Re-tune on a schedule (for example each quarter) rather than after every bad week.
