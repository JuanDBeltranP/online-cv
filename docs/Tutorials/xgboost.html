XGBoost 101: Cocoa, Weather and the Curve

Written in 2024. All examples use public data and are for learning only, not investment advice.

Gradient boosting builds trees one after another, each correcting the errors of the previous ones. XGBoost is the best-known implementation: fast, regularised and usually the strongest model on tabular data.

In this tutorial we predict the monthly direction of cocoa prices and see whether West African weather adds information beyond price momentum. The 2023/24 cocoa season, with record prices, makes a hard but instructive test.

1. Data

  • Cocoa prices: World Bank Pink Sheet monthly prices (see Part 2 of the regression tutorials for loading code).
  • Rainfall: CHIRPS monthly precipitation, averaged over the cocoa belt of Côte d’Ivoire and Ghana. You can export it from Google Earth Engine with the script in the Google Earth Engine tutorial, as a CSV with columns month and rain_mm.
  • ENSO: NOAA’s Oceanic Niño Index (ONI).
import numpy as np
import pandas as pd

rain = pd.read_csv("cocoa_belt_chirps_monthly.csv", parse_dates=["month"]).set_index("month")["rain_mm"]

df = pd.DataFrame({"cocoa": cocoa, "rain": rain, "oni": oni}).dropna()
df["ret"] = np.log(df["cocoa"]).diff()

2. Weather features that make agronomic sense

Raw rainfall is less useful than anomalies against the normal for that calendar month, and cocoa cares about accumulated stress over several months:

clim = df.groupby(df.index.month)["rain"].transform("mean")
df["rain_anom"] = df["rain"] / clim - 1

X = pd.DataFrame(index=df.index)
X["rain_anom_1m"] = df["rain_anom"].shift(1)
X["rain_anom_3m"] = df["rain_anom"].rolling(3).mean().shift(1)
X["rain_anom_6m"] = df["rain_anom"].rolling(6).mean().shift(1)
X["oni_lag2"]     = df["oni"].shift(2)
X["mom_3m"]       = df["ret"].rolling(3).sum().shift(1)
X["mom_12m"]      = df["ret"].rolling(12).sum().shift(1)
X["month"]        = df.index.month          # main crop Oct–Mar, mid-crop Apr–Sep

y = (df["ret"].shift(-1) > 0).astype(int)
data = X.join(y.rename("up")).dropna()

Every feature is shifted so it is known before the month we predict.

3. Training XGBoost

from xgboost import XGBClassifier
from sklearn.metrics import roc_auc_score, accuracy_score

train = data.loc[:"2018-12"]
valid = data.loc["2019-01":"2021-12"]
test  = data.loc["2022-01":]

feat = [c for c in data.columns if c != "up"]
model = XGBClassifier(
    n_estimators=1000, learning_rate=0.02, max_depth=2,
    subsample=0.8, colsample_bytree=0.8, reg_lambda=1.0,
    eval_metric="auc", early_stopping_rounds=50,
)
model.fit(train[feat], train["up"], eval_set=[(valid[feat], valid["up"])], verbose=False)

p = model.predict_proba(test[feat])[:, 1]
print("Best iteration:", model.best_iteration)
print("Test AUC:", round(roc_auc_score(test["up"], p), 3))
print("Test accuracy:", round(accuracy_score(test["up"], p > 0.5), 3))

Early stopping on a separate validation period picks the number of trees for us and is the single most effective guard against overfitting with boosting.

4. Tuning

With only a few hundred monthly observations, keep the search small and the trees shallow:

from sklearn.model_selection import GridSearchCV, TimeSeriesSplit

grid = GridSearchCV(
    XGBClassifier(n_estimators=300, learning_rate=0.03, eval_metric="auc"),
    {"max_depth": [1, 2, 3], "min_child_weight": [1, 5, 10], "subsample": [0.7, 1.0]},
    cv=TimeSeriesSplit(n_splits=5), scoring="roc_auc",
)
grid.fit(pd.concat([train, valid])[feat], pd.concat([train, valid])["up"])
print(grid.best_params_)

5. Explaining the model with SHAP

SHAP values show how much each feature pushed each prediction up or down:

import shap
explainer = shap.TreeExplainer(model)
sv = explainer.shap_values(test[feat])
shap.summary_plot(sv, test[feat])

Look for whether dry anomalies (negative rain_anom_3m) push the probability of a rise up, as agronomy would suggest. If the model relies on the opposite sign, be suspicious.

6. Ablation: does weather add anything?

Retrain without the weather columns and compare:

base_feat = ["mom_3m", "mom_12m", "month"]
m0 = XGBClassifier(n_estimators=model.best_iteration + 1, learning_rate=0.02, max_depth=2,
                   subsample=0.8, colsample_bytree=0.8).fit(train[base_feat], train["up"])
print("AUC without weather:", round(roc_auc_score(test["up"], m0.predict_proba(test[base_feat])[:, 1]), 3))

On monthly data the difference is often small, and that is a fair conclusion. Weather is far more useful at higher resolution: daily rainfall and soil moisture by region, mapped to crop calendars, combined with field reports on pod counts and disease.
